## Overview

Cachet uses a queue to send [mail](/v2.x/configuration/mail) and [beacons](/v2.x/installation/beacons) without slowing down the rest of the application.

## Supervisor

We recommend [Supervisor](https://www.digitalocean.com/community/tutorials/how-to-install-and-manage-supervisor-on-ubuntu-and-debian-vps) to manage the queue worker.

Supervisor monitors and controls long-running programs through a consistent interface.

## Cachet v2.4

```ini /etc/supervisor.d/conf/cachet.conf
[program:cachet-queue]
command=php artisan queue:work --delay=1 --sleep=1 --timeout=1800 --tries=3
directory=/var/www/cachet/
redirect_stderr=true
autostart=true
autorestart=true
user=cachet
```

## Cachet v2.3

Create a Supervisor configuration file named `/etc/supervisor.d/conf/cachet.conf`:

```ini /etc/supervisor.d/conf/cachet.conf
[program:cachet-queue]
command=php artisan queue:work --daemon --delay=2 --sleep=1 --tries=3
directory=/var/www/cachet/
redirect_stderr=true
autostart=true
autorestart=true
user=cachet
```

## Queues using the scheduler

The default installation sets the queue type to `database`. Cachet stores jobs in your database, and a cron job calls an Artisan command to process them.

Create a cron job. On Ubuntu, run `crontab -e` and add this line:

```bash /etc/crontab
* * * * * php /path/to/artisan schedule:run >> /dev/null 2>&1
```

Save and close the file. The cron job starts processing confirmation and incident emails.

## Synchronous queue

If you cannot add a cron job, you can process jobs immediately after they are created.

<Warning>
    Avoid this setup for larger installations with hundreds of subscribers. Each email can take a few seconds to send, which slows down your interaction with Cachet.
</Warning>

Set the following value in your `.env` file:

```ini .env
QUEUE_DRIVER=sync
```
