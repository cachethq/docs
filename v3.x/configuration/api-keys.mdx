API keys authenticate requests to the [Cachet API](/api-reference). Create a separate key for each service and grant
only the permissions that service needs.

## Creating an API key

<Steps>
    <Step title="Open API key settings">
        In the Cachet dashboard, open **Settings**, then **Manage API Keys**.
    </Step>
    <Step title="Create a key">
        Click **New API Key**. Enter a name that helps you identify the service that uses the key.

        Select an expiration date, or leave it blank for a key that never expires.

        Select the permissions the service needs. Leaving permissions empty grants full access.
    </Step>
    <Step title="Save the token">
        <Warning>
            Cachet displays the token only once. If you lose it, you must create a new API key.
        </Warning>

        Copy the token and store it securely.
    </Step>
</Steps>

## Permissions

API key permissions are called abilities. Leaving permissions empty grants full access.
The available abilities for each resource are:

| Resource | Abilities |
| --- | --- |
| Components | `manage`, `delete` |
| Component groups | `manage`, `delete` |
| Incidents | `manage`, `delete` |
| Incident updates | `manage`, `delete` |
| Incident templates | `manage`, `delete` |
| Metrics | `manage`, `delete` |
| Metric points | `manage`, `delete` |
| Schedules | `manage`, `delete` |
| Schedule updates | `manage`, `delete` |
| Subscribers | `manage`, `delete` |

The `manage` ability permits creation and updates. The `delete` ability permits deletion.
Most read-only endpoints are public unless your [API settings](/v3.x/configuration/cachet#api-access) require authentication.
Subscriber read endpoints always require the `subscribers.manage` ability.

## Revoking tokens

<Warning>
    Revoking an API key is irreversible. Services that use the key can no longer authenticate with it.
</Warning>

To revoke a key you no longer need, click **Revoke** next to the key.
